## The case against
1. Both traces are correct — `git -c k=v rm CLAUDE.md` (words[1]=='-c' matches no verb at `shell_guard.py:370-376`) and `bash --norc -c '...'` (`_INNER_SHELL_PAIRS` needs the adjacent pair, `:236`) both reach `Decision.allow()`. I reproduced both by hand; nothing below disputes the bugs.
2. They buy an adversary nothing. spec.md Design item (c) leaves `git reset --hard`, `stash pop`, `merge`, `pull`, `cherry-pick`, `checkout <branch>` **open and accepted** — flag-free, allow-listed under `Bash(git *)`, and each rewrites CLAUDE.md in the working tree. Anyone who can type `git -c k=v rm CLAUDE.md` can type `git reset --hard <sha>`. Closing the flag forms raises the bar by zero against the threat the item describes; it only tidies the accidental case, and no ordinary session writes `git -c core.fileMode=false rm`.
3. The intent's finding is "the Bash/PowerShell matcher ... never checks a command's target path" — an authorization-by-route gap. That route is now checked (hook registered, resolver, fail-closed rule, sandbox `denyWrite`). Escalating here restates the acceptance bar as "a complete shell parser", which the spec never promised and item (d) (variable, concatenation, base64 into an interpreter) makes unachievable in principle. A heuristic layer with a named ceiling was the design the owner accepted (`status.yaml: risk_accepted: [auth]`; spec Flagged concerns 1 and 3).
4. `bash --norc -c` **is** plan.md's named residual: "an unlisted wrapper ... still reaches a guardrail file at the hook layer alone". `_WRAPPERS` is a closed list of four words; `--norc`, `-lc`, `env -i bash -c` are all unlisted wrapper forms. Calling that "a different shape" is a distinction the plan's own sentence does not make.
5. The fifth bullet of the item leans on the prior round's committed `adversarial-review-c.json` and on `fix-requests.json`/`verifier.md` scope — i.e. on files under `changes/*/evidence/`, which REVIEW.md says not to report, and on process state that deferred review assigns to the gate, not to a reviewer. Strip it and the item is "a heuristic parser has two more holes", which is bullets 2-4.
6. Cost of parking: the shipped code today has **no** Bash path check and **no** sandbox `denyWrite`. Parking preserves the full original finding to litigate a two-line flag-skip. The honest asymmetry is the other way.
7. What I concede: spec.md Design lists `git rm` as a covered idiom without qualification, so the implementation under-delivers a *stated* line — a compliance nit, fixable by a follow-up change plus one qualifying clause, not an Important finding under REVIEW.md ("would break behavior, leak data or breach a policy" — this neither breaks working behavior nor widens exposure past the accepted baseline).
8. I would accept escalation if any of these held, and would flip on any one: the flag forms were the *only* literal git/shell route to a guardrail file (they are not — item (c)); the exposure were CI-reachable with the sandbox in force (it is not; the residual is by-hand/native Windows, already named and accepted); or the fix were structural rather than running `_nonflag`-style skipping before `words[1]` in two places.

# Security & policy brief, gate (deploy)

## auth
- Verdict: continue
- What the change does to it: `plugin/detect/cli.py` `_human_label_actor` now refuses an `sdlc:go` label from any account that fails `state.unpark.is_owner_actor` (decision 34). The check reads the owner from the default branch's `sdlc.yaml` (the `approved` copy `cmd_go` passes), so only the owner's account can authorize a runbook. A refused label performs nothing and stays on the PR. This round (4958e80) leaves the auth path as it was. It changes the eval runner (`plugin/evals/run.py`, `framework_root`): only the framework suite (`--fixture`) runs a case's setup and command checks in the framework root, with the credential-stripped `check_env`. A project's suite fails such a case before any run. `docs/OPERATING_MODEL.md` now says the Go requires the owner's account.
- What could break: A Go applied from a collaborator's account is now refused, and the reason names the owner's account. On an organization repository, every Go is refused (fail closed) until the default branch's `sdlc.yaml: owner` names the owner. A framework case's setup could write into the framework checkout. Today only case 0006 sets `framework_root`, it has no setup, and the framework-evals job has `contents: read`.
- How to undo it: Revert the commit that adds the `is_owner_actor` check and its import in `plugin/detect/cli.py`. That brings back the weakness this incident reported. To undo only the runner key, revert 4958e80's `plugin/evals/run.py` hunks together with the `framework_root: true` line of case 0006.

# Security & policy brief, gate (deploy)

## auth
- Verdict: continue
- What the change does to it: `plugin/detect/cli.py` `_human_label_actor` now also refuses an `sdlc:go` label whose actor fails `state.unpark.is_owner_actor` (decision 34), with the owner read from the default branch's `sdlc.yaml` (the `approved` copy `cmd_go` already passes), so the head cannot name its own owner; a refused label runs nothing, writes nothing and stays on the PR. Separately, `plugin/evals/run.py` adds `framework_root`, which lets a case of the framework suite (`--fixture`) only run its setup and command checks in the framework root; a project's suite fails such a case before any run.
- What could break: A Go from a collaborator's account, which used to run the runbook, is now refused with a reason naming the owner's account; on an organization repository every Go is refused (fail closed) until the default branch's `sdlc.yaml: owner` names the owner's login. A `framework_root` case's setup could write into the framework checkout that later cases load; today only case 0006 sets the key and it has no setup.
- How to undo it: Revert the `is_owner_actor` import and the four-line check in `plugin/detect/cli.py`, which restores the reported weakness; to undo only the runner key, revert the `plugin/evals/run.py` hunks together with case 0006's `framework_root: true` line and its test in `tests/test_evals.py`.

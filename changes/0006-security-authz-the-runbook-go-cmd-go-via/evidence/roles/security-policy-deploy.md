# Security & policy brief, gate (deploy)

## auth
- Verdict: continue
- What the change does to it: `plugin/detect/cli.py` `_human_label_actor` now refuses an `sdlc:go` label whose actor fails `state.unpark.is_owner_actor` (decision 34). It reads the owner from the default branch's `sdlc.yaml` (the `approved` copy `cmd_go` already passes), so a PR head cannot name its own owner. A refused label runs nothing, does not change `runbook_authorized_by` and stays on the PR. Separately, `plugin/evals/run.py` adds `framework_root`: only a case of the framework suite (`--fixture`) may run its setup and command checks in the framework root, and a project's suite fails such a case before any run.
- What could break: A Go from a collaborator's account used to run the runbook and is now refused, with a reason that names the owner's account. On an organization repository whose default-branch `sdlc.yaml` does not set `owner:`, every Go is refused (fail closed) until that key names the owner's login. A `framework_root` case can write into the framework checkout that later cases load; today only case 0006 sets the key, and it has no setup.
- How to undo it: Revert the `is_owner_actor` import and the owner check in `plugin/detect/cli.py`; that brings back the reported weakness. To undo only the eval runner key, revert the `plugin/evals/run.py` hunks, case 0006's `framework_root: true` line and its test in `tests/test_evals.py`.

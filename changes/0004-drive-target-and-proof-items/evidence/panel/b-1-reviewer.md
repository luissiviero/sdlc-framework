## Verdict
Keep the `$SDLC_PROOF_DIR` form and no substitution in `collect.py`; add the Windows note to the R1 comment and the R10 text (a nit, not a reason to reopen).

## Why
- The intent fixes the form: "a Playwright line that writes to `$SDLC_PROOF_DIR`" (intent.md line 153, Q4 of choice 246). The design follows the intent; the compliance pass of REVIEW.md measures the design against it, and a design run cannot reopen an owner-accepted outcome.
- Where the gate judges the proof, the shell expands it: every phase workflow is `runs-on: ubuntu-latest`, so the runner's step runs under `/bin/sh` (docs/notes/40.md §46, verified). The Windows case is the by-hand `collect.py` run only, through `run_command` (`plugin/gate/checks.py:306-328`, `shell=True`, `cmd.exe /c` on `os.name == "nt"`).
- On that path the failure is loud, not silent: `cmd.exe` leaves the literal, Playwright writes under `.\$SDLC_PROOF_DIR\`, `proof/` stays empty, every item is `not produced`, `collect.py` exits 1 and prints the items (spec R2, Design "Error behaviour"; plan Risks "Playwright's `--output`": "a wrong line costs `not produced` items and a round, never a silent pass"). By REVIEW.md's bar it breaks no gate behaviour, leaks nothing and breaches no policy, so it is not Important.
- Decision 7 and `detect.py`'s docstring ("runs identically on Windows ... decision 7") bind the plugin's runtime and the `python -m` / `npm` shape of detected targets; the drive line is project content the owner confirms in the change-0000 PR (Q4: "`/sdlc-init` only proposes and the owner confirms"). The plugin code the item touches (`run_drive`, `clear_proof_dir`, `collect.py`) stays Python and portable (plan Risks "Windows").
- Substitution in `collect.py` is rightly refused (plan "Options not taken"): the by-hand run would differ from the runner's, and a plugin-side rewrite of the owner's shell string is a new mechanism the owner never decided (coding-standards rule 2; security-baseline rule 2 on building shell commands from data). The shell-free alternative, `outputDir` from `process.env.SDLC_PROOF_DIR` in `playwright.config`, needs a skeleton file the intent forbids ("No skeleton file is written").
- Safest reading, and the one gap: ux-conventions rule 4 (say what happened and what to do next) puts the fact in the text the owner reads. The `commands.drive` comment (R1) and `sdlc-init.md`'s step 0 (R10) should say the variable is expanded by the platform shell and name `%SDLC_PROOF_DIR%` for a `cmd.exe` by-hand run or `process.env.SDLC_PROOF_DIR` in the config. One sentence inside files already in the plan; no plan change, no park.

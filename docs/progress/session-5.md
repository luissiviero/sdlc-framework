## Choices made where the pack left it open (continuing session 4's numbering)
66. **Runtime of the loop: a CI step** (37.4): the scheduled `sdlc-detect.yml`, not an Agent SDK service — the trigger table of §4.2 is workflows, no webhook source exists, and decision 7 forbids a runtime dependency. `workflow_dispatch(force_tier)` rehearses the whole loop on demand and is recorded as `forced` in the detection record.
67. **Observations and the window** (37.1, 37.2): one observation per UTC day = failed runs / counted runs (completed, `success` or `failure`, events push / pull_request / schedule / workflow_dispatch, workflows not named `SDLC …`; `source: github-actions:<workflow name>` narrows to one); `baseline: rolling_<N>d` is the window; the baseline never contains the points it judges: the last eight points of the window are the tail the rules read, the rest the baseline (mean, sample standard deviation); fewer than eight baseline points → tier 0 "insufficient baseline".
68. **The rules and their tiers** (37.1): the four classic Western Electric rules, each satisfied by a run ending at the latest point (an older breach inside the tail was reported by an earlier run): `we1` one point beyond 3σ → 3σ; `we2` two of three beyond 2σ → 2σ; `we4` eight points on one side of the mean → 2σ (a shift of the mean is the slow drift p.43 wants diagnosed); `we3` four of five beyond 1σ → 1σ (the early warning that only logs). Ties: the highest tier, then `we1`, `we2`, `we4`, `we3`. `direction: above` by default (a failure rate is worse when higher); `sigma == 0` makes any point above the mean an infinite breach — the article's own example (p.45: one bad day after a clean month) — and `min_sigma` is the owner's floor.
69. **One finding per metric at a time** (37.4, p.44 step 6): the detection skips filing while an incident of the metric is in flight (a remote `sdlc/<id>/a` with a detection record for the metric, not abandoned, and not at phase e on the default branch) or while its signature is dismissed; a finding is "the same" when the same metric trips the same rule (`detect|metric|rule`), a detection dismissal expires after one baseline window, a scan dismissal never.
70. **The proposal is the diagnosis's, the verdict the dispatcher's** (37.4, 37.5): the model writes `evidence/proposal.json` (route, args, rationale); `detect/cli.py dispatch` validates it against the tier and `bands.yaml`, resolves the authorization (the bands' value; a stricter `go` in `sdlc.yaml: maintain.runbooks` wins; decision 26 on top) and acts; a refused proposal is rewritten once by the run and then parks with the reason. At 2σ the only route is `pull_request`; the intent PR is the diagnosis's whole artifact (p.44 step 5).
71. **"Go" is a label** (37.4, decision 14): `sdlc:go` on the incident PR, read by `sdlc-runbook.yml`, performed once by `detect/cli.py go` when a person applied it (never the token or a `[bot]`), recorded as `status.yaml: runbook_authorized_by`, the label removed — the un-park labels' shape (decision 24). A comment is never a Go.
72. **The two shipped runbooks never touch a test and never merge** (37.4, p.45): `quarantine-flaky-test` adds `--deselect <node id>` to pytest's `addopts` (`pytest.ini`, `pyproject.toml`, `tox.ini`, `setup.cfg`, in pytest's order; created when none exists) on `sdlc/<id>/quarantine` and opens the PR (Python projects only; a Node project gets "unsupported" and the intent PR alone); `revert-pr` reverts one commit of the default branch (`-m 1` for a merge) on `sdlc/<id>/revert-<sha7>` and opens the PR; both idempotent; a project's own runbook is a `command` under `maintain.runbooks`, run without a shell like `deploy.command`.
73. **An incident change stays at phase f until its intent PR is merged** (39.1): the maintain run leaves `status.yaml: phase: f` on `sdlc/<id>/a`; the design workflow's guard accepts `f` as the phase before (b) (`PHASE_BEFORE`), so the owner's merge is gate (a) of that change (decision 25) with no write to the default branch; `read_status(on_default_branch=True)` needs nothing new. The PR title is `maintain(<id>): …`, the gate label `sdlc:f-ready`, plus `incident`.
74. **Every security finding is an incident intent** (38.1, decision 16): a bounded finding becomes a `change_type: fix` intent whose Proposed outcome is the patch, with the reviewer's suggested diff in `evidence/suggested-patch.diff` for the build run; a wide one a `feature` intent describing the class; at most three per weekly run; no route skips gates (a) and (b). The vulnerability-class eval (p.47 step 7) is the incident's eval of step 36. The scanners (`pip-audit`, `bandit`; `npm audit`) run in the same workflow, reported as artifacts, never a gate: the owner reads them; a finding worth a change is filed by the review.
75. **The eval runner is the framework's own** (35.1, 35.2): `claude plugin eval` loads only the plugin in a throwaway workspace, has no custom-code graders, puts a repository into a run only through a Bash scaffold script, doubles the cost with its baseline arm and can be switched off server-side (NOTES §13a); the framework's per-project suite tests the project's `CLAUDE.md`, hooks and settings (so the runner never passes `--bare`) with checks that are commands and file states. Cases are `prompt.md` + `checks.yaml`; the report is JSON; the pass rate is the job's verdict.
76. **Every hook logs every decision** (41.1): `run_hook` appends the line (a hook that crashes logs its fail-closed block too); the cost is one `git rev-parse` per hook call to find the change's evidence folder, inside every hook's time budget; the production gate keeps computing its own path (choice 39). The log is evidence, committed with the change, and an artifact of every phase run.
77. **The counters ride in the digest** (42.2): `pr/counters.py` over the change folders of the default-branch checkout; no report PR (the guide's "you merge or ignore" would be one more queue item), no model; the digest issue's last section.
78. **`evals/check.py` locates the framework** (35.3): `--framework`, `$SDLC_FRAMEWORK_DIR`, or `framework/` beside `evals/` (the CI checkout); a project runs its suite by hand with the framework checkout it pins.
79. **A bands change is a `bands.yaml` PR** (39.1, p.44 step 6 "Dismissals tune the bands"): the dismissal store mutes a metric + rule pair for one window; widening a band is the owner's edit of the file, reviewed like any project content; nothing in the loop writes `bands.yaml`.
80. **The dispatcher is a CI step of its own and judges by the approved copies** (review finding 2): `sdlc-detect.yml` runs the model with `--diagnosis-only` (the intent and the proposal, committed) and then `detect/cli.py finish` (dispatch, gate (f), evidence, the PR) with the project's runbook secrets in that step's environment only; `dispatch`, `finish` and `go` read `bands.yaml` and `sdlc.yaml` from `origin/<default>` through `git show`, so an uncommitted edit in the session — a prompt injection in a failed-run log could ask for one — changes no authorization (decision 14 "enforced, not remembered"; decision 11).
81. **A forced finding never pre-approves a runbook** (review finding 3): `force_tier` is a rehearsal with no breach behind it; decision 26's pre-approval and a bands `preapproved` are for a real 3σ, so every runbook route of a forced finding resolves to `go` (the intent PR still opens; the owner's `sdlc:go` runs the runbook if wanted).
82. **Only complete UTC days are judged** (review finding 6): the daily run at 05:41 UTC drops today's observation before evaluating, so the latest point is yesterday's full day; the log still records every run.
83. **A pending dismissal already mutes** (review finding 7): the detection reads the dismissal entries of every `origin/sdlc/<id>/dismiss` branch beside the default branch's store, and the incident folders on the default branch beside the remote `sdlc/<id>/a` branches, so neither the day between a close and the dismissal PR's merge nor a deleted merged head refiles a finding.

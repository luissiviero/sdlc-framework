## What was built
1. **The runner saves its state as the run goes** (`plugin/ci/run_phase.py`, `save_cancel_state`), in `$RUNNER_TEMP/sdlc-run.state.json` beside `--out` (outside the checkout the session writes), at four stages: `prepared` after the guard (the phase, the change, the gate's phase, the prepared branch, the fix branch, the park the change already had); `session` right before the session (the head before it, `status.yaml` before it, the name of the result file the runner will store, and the snapshots the checks after the session compare with: the runner's own files, the stored results, the requests file, the change's remote refs); `after` once the runner's own checks after the session passed; `done` once the run's PR is updated, before its hand-over. A run starts by removing a stale state; a dry run and the review pass save none. On GitHub's interrupt the runner's own `finally` does nothing (no half park, no result file), so the step after it parks.
2. **`run_phase.py --phase <phase> --cancelled`** (`run_cancelled`) parks from that state, with no model and no session:
   - nothing to park: no state (the job was cancelled before the runner started the change's run), `done`, or a state that is not this run's (`cancel_state_refusal`: the change folder must be the change's own under `changes/`, the branch the phase's, a fix round's head the one the workflow checked out, `HEAD_REF`; the project's own commands run outside the sandbox in the same job and could rewrite the file);
   - a park the run wrote before the cancel (outside `session`): published again with the review request, its reason kept;
   - at `session`, the checks after the session are replayed from the snapshots, with the default branch's copies of `sdlc.yaml` and `status.yaml` read afresh (`replay_session_checks`); what they find is restored and parks, keeping no work, as the runner does;
   - a fix round at `prepared` or `session`: `park_unfinished_round` with the cancel as its reason: the session's uncommitted work in one commit on the PR's head, not gated, the change parked, `sdlc:fixing` replaced; an automatic round with nothing to keep gets decision 29's own park (`release_unfinished_round`); at `after` the commands step had run in the tree, so nothing uncommitted is kept and the round parks with check `cancelled`;
   - design, build, test and deploy: the change folder committed with the reason and the park, check `cancelled`, as the runner's timeout park does (decision 11's note of 2026-10-23);
   - the reason tells GitHub's cancel at the job's `timeout-minutes` from a cancel by hand (the Actions API's `started_at` of the job on this runner against `SDLC_JOB_TIMEOUT_MINUTES`), or says it cannot tell and why; no re-run;

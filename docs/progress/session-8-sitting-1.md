## Choices made where the pack left it open (continuing session 7's numbering)
95. **The pin step is the one `run:` line that is not plain `python`**: `git show <ref>:<script> | python - …` under `shell: bash`, so the script the head carries never runs and a failed `git show` fails the step (pipefail). The rule "every run line calls python" stands with this one documented exception, asserted by name in the tests. What this does not close: on a `pull_request` event GitHub runs the head's own workflow file, so a head that rewrites the workflow can still call anything before the framework is checked out; the fully qualified ref is the substantive fix, the script's provenance is defence in depth, and `.github/workflows/**` in a project's `protected_paths` parks such a branch only once `run_phase.py` runs (recorded in OPERATING_MODEL §4.2 and NOTES §16).
96. **A failed setup step in the runbook job is a park with the Go consumed**: the job goes on past the failure and ends green, the park is on the incident PR with the step's error line and the run URL, and `sdlc:go` is removed so the owner's next application is a fresh `labeled` event (an application while the label is still present fires nothing). No runbook and no model run on that path.
97. **The fix round's file is the only source in CI, and by hand only while it is current**: `evidence/fix-requests.json` is read when it exists, `unavailable` is null and its `head` is the current HEAD (a by-hand round after a commit gathers afresh with the same rule). The private-membership case is not solved — GitHub reports what it reports — but it is now visible: the dropped author and why are in the file and in `fix-response.md`. A reader that fails makes the whole collection unavailable rather than an empty list the session would read as "nothing to do".
98. **`origin` must be the repository, on a runner always**: `approved_files` compares `origin`'s URL with `--repo` (else `$GITHUB_REPOSITORY`) before the fetch; another GitHub repository is refused anywhere, a URL that is not a GitHub repository only when `GITHUB_ACTIONS` is set (a runner's checkout always has the repository's URL; the tests and a by-hand run push to a local bare repository). Not the project's `automation_identity` or any config: the expected name comes from the workflow's own variables.

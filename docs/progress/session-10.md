## Choices made where the pack left it open (continuing session 9's numbering)
104. **The runner's check is a snapshot and a comparison, not a second read of GitHub**: the label events cannot tell a forged `risk_accepted_by` entry from a real one (an event names the label and the actor, not the items), so what the session may leave in the owner-only fields is exactly what stood when it started (the runner's own label handling included), what the default branch's copy carries (a merge of the default branch into the work branch brings it), and a cleared field (fails closed at the gate; `lock_tests()` clears `tests_unlocked_by` by design). The fields are restored before any commit of the run, so no runner commit ever carries the session's version and the next run's snapshot is trustworthy by induction; a session that committed and pushed the forged values itself leaves that commit in the branch's history, where the gate's `owner_actions` sees an automation commit whose recorded actor is a person — but HEAD no longer accepts the item, so `risk_list` parks on it. The overrides are not part of the park: they are ignored wherever they are read (105) and a change of them is reported.
105. **Which copy of `status.yaml` is "the owner's"**: the base branch's tip — the gate reads `d.base` (the ref `diff.collect` resolved: `origin/main` or a local `main`), the runner the remote-tracking `refs/remotes/origin/<default>`, the panel CLI what the gate reads — so the three agree (the review of the diff, M3: at the merge base the gate and the guard disagreed after an owner's change on `main` and the run stalled without a park). `intent.md` stays at the merge base by design (`approved_artifact`). A folder not on the default branch yet (an intent PR before its merge) has no approved override: the project's profile and review mode apply, and at (a) every gate is human anyway. With no remote-tracking ref at all the checkout's values stand by hand only; on a runner no override applies. An unreadable approved copy fails closed (the gate raises, the runner's guard skips).
106. **One reader for the two booleans, fail closed where a wrong reading opens something**: `config_flag` raises on anything that is not a boolean; the gate's `limits`, the preflight, the runner's guard, the production-gate hook and the release workflow refuse on it (a park, a skip, a block, exit 2), while `detect/routes.py`, `pr/description.py` and `state/cli.py` read False (the closed side there: a rollback keeps its `go`, a release line stays off). The message names the key path and the value; a parsed mapping has no line number.

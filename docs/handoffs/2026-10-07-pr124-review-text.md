Request changes on PR #124 (design(0003)). Re-run the design pass with the decision and the corrections below; keep intent.md unchanged.

**Decision on the open flagged concern**
1. Concern 1 (the `class` tag's vocabulary): decided. The class is free text in kebab-case; `index.py build` normalises it (lower-case; spaces and underscores to hyphens; one heading per normalised value), so a spelling drift cannot create a second heading. For an incident the weekly scan filed, the class is the `class` field of `evidence/scan-finding.json`. No controlled vocabulary now: no lesson exists to name one from (decision 17), and a list would be a guardrail edit on every project. Revisit when a project has ten lessons. Rewrite the item so it starts with "decided".

**spec.md**
2. Gate scope: the new lesson, eval and `check` sub-checks run at gate (e) only. State the guard explicitly: `ctx.status.entry_route == "incident" and ctx.phase == "e"`. Today the incident branch of `check_artifacts` sits inside the `intent.md` block, which every gate (a) to (f) runs, so without the guard every incident parks at (f) with "lesson missing" and `tests/test_gate.py::test_gate_f_waits_for_the_owner_s_triage_with_the_finding_and_its_route` turns red. Name that test as the regression guard.
3. One "what I need from you" line per failure: `check_artifacts` joins every problem into one failure with one fixed need text, so the requirement cannot be met inside that function as the Design says. Decided: a separate check `lesson_and_eval` registered at phase "e" in `CHECKS_BY_PHASE`, returning one CheckResult whose `need` lists one line per problem. Drop the "no new CHECKS_BY_PHASE entry" constraint. Add a test that asserts the rendered what-I-need text.
4. `(stale)` and a byte-exact `check` contradict each other: the day a lesson passes `stale_after`, `build` output changes with no file changed, `check` fails, and the maintain run falls back to every file until the next incident. Decided: `check` compares the index with the `(stale)` suffixes stripped from both sides, and `build`/`check` take `--today YYYY-MM-DD` for the tests. Write it under Requirements and Acceptance.
5. The glob "every `lessons/*.md`" includes `README.md` (copied into every project by `/sdlc-init`) and `index.md` itself. Exclude both by name. State that an `## Unsorted` entry (a file without a parsable frontmatter) does not fail `check`; it is listed and `check` prints a one-line note per Unsorted file. A frontmatter that does not parse is Unsorted with the parser's error in the note, never a crash.
6. Frontmatter notation: the project's YAML reader (`plugin/state/yamlish.py`) refuses flow style (`fixed: {pr: 42}` raises "flow mappings are not supported") and truncates an unquoted value at ` #`. Require block style for every nested field, and double quotes on `title` and `description`, in the README example and in step 0b. Read lesson files with `utf-8-sig` before the frontmatter split.
7. Concern 3 (Windows newline stability) was closed on a wrong basis: `yamlish.dump_file` dumps YAML and cannot write the markdown index, and a concern may be closed only by a policy or the owner, not by code. Reopen it and close it as decided by the owner with the real mechanism, stated as a requirement: the index is written with `write_text(..., newline="\n")`, `check` compares text read in universal-newline mode (a CRLF checkout must not false-positive), and every link uses `as_posix()` (the intent's forward-slash constraint, which the spec dropped).
8. `runbook` source: the "resolved route" reasoning does not hold (`Resolved.route` is always the proposal's route; `runbook_authorized_by` is set only for `go` routes). The source is `evidence/proposal.json: route` when `evidence/runbook-<name>.json` exists with `status: ran`; absent otherwise (failed or go-requested included). Make Requirements and Design say the same thing.
9. Scan-filed incidents: an incident the weekly scan files carries `evidence/scan-finding.json`, not `detection.json`; `finding.read_any` maps it to metric `security: <class>`, rule `scan`, tier 3, and there are no failed-run URLs. Add one requirement: `detected` is read through `finding.read_any`, the `detection` source points at whichever file exists, `run-<n>` sources are absent for a scan incident, and the class tag is the scan's `class` field (item 1).

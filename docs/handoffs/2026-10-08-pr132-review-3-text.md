Request changes on PR #132 (build(0003)). A fresh-context review of the diff found these; each was reproduced on the branch. Fix them in the files plan.md already lists, with a test each where one is named; no change to spec.md (choice 164), plan.md only where the file list or a step changes.

1. plugin/gate/checks.py `_lesson_field_problems`: the check reads only that `detected`, `fixed`, `generated` and `sources` are non-empty, never what is inside them, so a lesson whose `detected` lacks `at` or `tier` passes gate (e) while `plugin/lessons/index.py build` sends the same file to `## Unsorted` ("missing detected.at or detected.tier"). Require `detected.at`, `detected.metric`, `detected.tier` and `detected.rule`, `fixed.pr`, `generated.by` and `generated.at`, and `id` and `resource` on every `sources` item; and fail the check whenever `index.read_entry(lesson).ok` is false, naming `entry.error`, so the gate never passes a lesson the index cannot render. One fail case each.
2. An unquoted metric tag of the scan's shape (`- security: sql-injection`) parses as a mapping: the gate passes it (`tags` is only "a non-empty list") and the index line prints `{'security': 'sql-injection'}`. In the gate require `tags` to be a list of non-empty strings; in `index.py` send a lesson with a non-string tag to `## Unsorted`; in `template/lessons/README.md` and `/sdlc-deploy` step 0b write every tag double-quoted (`- "<metric>"`), as `title` and `description` already are.
3. plugin/lessons/index.py `_read_text` catches `OSError` only: a lesson saved in cp1252 (one hand-written file is enough) raises `UnicodeDecodeError` out of `build`, `check` and the gate check — the gate then parks on "check crashed" instead of naming the file, against the spec's "never raises". Catch `UnicodeDecodeError` too and send the file to `## Unsorted` with the reason; a test with a cp1252 file.
4. index.py `read_entry` stores `stale_after` unconverted, so `stale_after: 20271008` (an unquoted date-like number) raises `TypeError` in `_date_only` from `build`, `check` and the gate. Convert with `str()` or send the file to `## Unsorted`; a test.
5. index.py `main` prints the diff and the `## Unsorted` notes to stdout without the UTF-8 reconfiguration every other CLI of the plugin applies (`hooks/_common.py: utf8_stdout`, as `release/notes.py` does): on a Windows console a description with `σ` raises `UnicodeEncodeError` and the diff is lost. Call `utf8_stdout()` at the top of `main`.
6. `_render_line` always appends `.` after the description, so a description that ends with a period renders `..`; spec.md line 91 says the description "carries no trailing period", but neither the README nor step 0b tells the writer. Strip a trailing period in `_render_line` (`description.rstrip().rstrip(".")`) and say in the README's `description` line that the period is added by the index; a test.
7. `build()` creates `lessons/` (`mkdir`) and `check()` and the gate check call it, so a `check` or a gate run on a project without `lessons/` creates the folder as a side effect (`gate.evaluate` is documented "no side effects"). Move the `mkdir` into `main`'s `build` branch.
8. The gate's message for a field of the wrong type says "missing frontmatter field" (an unquoted `change: 1000` is an int, so "missing"). Word it "missing or not a <kind>".
9. The `## Unsorted` label of a new-shape lesson is the body's first heading, "What happened", even when the frontmatter carries a valid `title`; use `title` when it is a non-empty string, else the first heading, and change the test that locks in `[What happened](…)`.
10. `lesson_and_eval` returns `reason` and `need` as the same list, so the "what I need from you" block prints every problem twice; make `reason` a count ("4 problems with the lesson and the eval case"). The index-drift line should say what to do: "run `python "${CLAUDE_PLUGIN_ROOT}/plugin/lessons/index.py" build --root .` and commit lessons/index.md".
11. tests/test_gate.py has no pass case for a lesson whose `supersedes` target is retired: a gate that rejects every `supersedes` passes the suite (reproduced by mutation). Add the pass case.
12. The eight fail-case tests assert a substring of `need`; spec.md's Acceptance asks each to assert the rendered "what I need from you" block. One helper comparing `GateResult.what_i_need()` with the full expected text, used in every fail case.
13. State in `template/lessons/README.md` and step 0b whether the `runbook` frontmatter field keeps the route's `runbook:` prefix as `evidence/proposal.json: route` carries it (`detect/routes.py: RUNBOOK_PREFIX`) while the tag is the bare runbook name; today the three places disagree.
14. Wording: `docs/OPERATING_MODEL.md` line 144 "a heading per tag" → "a heading per first tag (the class)"; the `index.py` docstring repeats the spec's contradictory "`## Retired` last … `## Unsorted` after that" — say "`## Retired`, then `## Unsorted` last".
15. index.py `_render_line` and `_render_unsorted_line` put `title`, `description` and the first heading into a markdown link unescaped, so a `]` or `(` in a title breaks the link (the (e) review pass's nit); escape `]` and `)` in the link text and target, or reject such a title into `## Unsorted`.

Not asked for here (the owner's call, carried as a known gap): the maintain step's "or the rule that fired" cannot be matched on the index line, which carries tags only; adding `detected.rule` to the line is a spec change.

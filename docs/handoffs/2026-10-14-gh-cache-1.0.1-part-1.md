## 2. What `gh` writes, and where

The sources are `gh` 2.89.0, which is installed here; `github.com/cli/cli` at tag v2.89.0 (commit `b626711`); and `github.com/cli/go-gh` v2.13.0, its dependency (`go.mod:19`).

| Fact | Status | Source |
|---|---|---|
| The cache folder is `$XDG_CACHE_HOME/gh`, else `$HOME/.cache/gh` on Linux. `os.TempDir()/gh-cli-cache` is used only when `HOME` cannot be resolved | verified | go-gh `pkg/config/config.go` `CacheDir()`, lines 296-314; the four functions were copied into a Go program and run here |
| There is no `GH_CACHE_DIR` variable | verified | `grep` over both source trees, empty; a demo with it set still gives `$HOME/.cache/gh` |
| `XDG_CACHE_HOME` is implemented but not documented: `gh help environment` lists `GH_CONFIG_DIR` only | verified | `gh help environment` output (2.89.0) |
| `--log` and `--log-failed` write exactly one thing: on a cache miss, `os.MkdirAll(<cache>, 0755)`, then `<cache>/run-log-<run id>-<started>.zip`. The zip is always read back from disk, so there is no in-memory fallback, and a failed `MkdirAll` aborts the command (`failed to get run log: creating cache directory`) | verified | cli `pkg/cmd/run/view/view.go`, lines 45-62, 64-71, 148-158, 308-321 and 489 |
| Nothing else writes during this call. The config dir is only read (no migration write without a legacy config). The update check (`state.yml`) is skipped when `CI` is set or there is no TTY, and its failure is ignored anyway. The extensions dir is only `stat`ed. There is no telemetry | verified | cli `internal/ghcmd/cmd.go:53-70, 217-226`; `internal/update/update.go:79-87, 188-191`; `strace` of `gh --version` and `gh config list` under an empty or `chmod 555` `HOME`, both exit 0 |
| `gh` versions other than 2.89.0 behave the same | not verified | — |

**So one variable is enough:** `XDG_CACHE_HOME`, pointing at a folder the sandbox lets the session write. `HOME` must stay set. `GH_NO_UPDATE_NOTIFIER`, `XDG_STATE_HOME`, `GH_CONFIG_DIR` and `XDG_DATA_HOME` are not needed.

## 3. The options

| | **A. The runner points the cache into the checkout** (recommended) | **B. An allow rule for `gh`'s default cache** | **C. A dedicated folder outside the checkout** |
|---|---|---|---|
| The change | `session_env` sets `XDG_CACHE_HOME=<root>/.sdlc-cache`, and `RUNNER_EXCLUDES` gains `/.sdlc-cache` so the gate never sees the folder as a stray | `settings.ci.json` gains `sandbox.filesystem.allowWrite: ["~/.cache/gh"]`; no environment change | `session_env` sets `XDG_CACHE_HOME=$RUNNER_TEMP/sdlc-gh-cache`, and `ci_settings_file` adds that absolute path to `allowWrite` |
| What the session can now write that it could not before | Nothing new. The checkout is already a default write root (S); `gh` now writes there | `/home/runner/.cache/gh` and everything below it | One folder under `RUNNER_TEMP` |
| Does it widen what the model can reach (decision 6)? | No. There is no new sandbox or permission entry, and `settings.ci.json` is unchanged | Yes, by one folder outside the checkout: the first `allowWrite` entry in the CI settings | Yes, by one folder outside the checkout, created by the runner at run time |
| Side effects | A new folder in the working tree. It is never committed, because commit-phase stages the change folder only (`run_phase.py:362`), and `.git/info/exclude` hides it from `git status`. `.zip` files are not picked up by `ruff`, `pytest` or `compileall` | The folder stays outside the tree | Two mechanisms (an environment variable plus a settings rewrite). `RUNNER_TEMP`'s value is not verified in GitHub's docs |
| The test that proves it (red on today's code, green on the fix) | `session_env(env, root)[XDG_CACHE_HOME] == <root>/.sdlc-cache`; a variable the workflow already set is overridden (only the checkout is known to be writable); `write_git_exclude` writes `/.sdlc-cache` | `ci_settings_file(...)` carries `allowWrite == ["~/.cache/gh"]` and nothing else | The A test, plus `ci_settings_file` carrying the folder's absolute path in `allowWrite` |
| Files touched | `plugin/ci/run_phase.py`, `tests/test_ci.py` | `plugin/ci/settings.ci.json`, `tests/test_ci.py` | `run_phase.py`, `tests/test_ci.py` |

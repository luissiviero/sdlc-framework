Request changes on PR #132 (build(0003)). Three findings of the fresh-context review of the diff are fixed in this round, with a test each; the rest is the owner's choice.

**Fix in this round**
1. `plugin/gate/checks.py`, `_supersedes_problem`: the `supersedes` value is joined to `lessons/` unchecked, so `supersedes: ../secret.txt` reads a file outside `lessons/` and the gate quotes that file's first unparsable line into the "What I need from you" text (`yamlish`'s error messages carry the offending line); an absolute path passes when it points at a retired lesson anywhere, and a lesson that supersedes itself passes. Decided: a `supersedes` value must be a bare file name matching `[0-9][0-9][0-9][0-9]-[0-9][0-9]-*.md` (`Path(value).name == value`), not the lesson's own name; anything else is one problem line "supersedes must name a lesson file in lessons/"; the "is unreadable" line names the file only, never the parser's message. One test per case in `tests/test_gate.py`.
2. `plugin/lessons/index.py`: the spec says a bad file never stops the build, but three parsable frontmatters crash `build` and `check` with a traceback — `stale_after: 2027` (an int: `TypeError` in `_date_only`), `detected.at: "2026-13-01…"` (`IndexError` in `_month_label`), and a lesson file that is not UTF-8 (`UnicodeDecodeError`, which `_read_text` does not catch: it catches `OSError` only). Through the gate this becomes a "check crashed" park that hides the real problem. Decided: each goes to `## Unsorted` with a note naming the field and the reason (`_read_text` catches `UnicodeDecodeError` too; `_date_only` and `_month_label` accept a string of the right shape only). One `tests/test_lessons.py` case per input.

Add "plus every lesson under `## Unsorted`" and assert it in `tests/test_commands_and_skills.py`.

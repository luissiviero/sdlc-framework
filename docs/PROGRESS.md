## Summary
- **Where the lookups came from** (a logging `sitecustomize` with the Python caller of every git process, one run of `test_the_evidence_logs_are_written_by_the_runner_after_the_session_outside_its_sandbox`): one `run_phase` process asked `rev-parse --is-inside-work-tree` 13 times (`gitops.is_repo` and `gate/diff.py`'s `is_repo`) and `rev-parse --verify --quiet refs/remotes/origin/main` 11 times (four from `gitops.default_branch`, two from `gate/diff.py`'s `default_base`, five from the runner's `_ref_exists`), with a `fetch`, a `checkout` and the session in between.
- **`gitops.remembered(root, what, ask)`:** an answer is remembered per process, keyed by the checkout's real path, `GIT_DIR` and `GIT_WORK_TREE`, until the process starts anything but a read-only git query. An audit hook (`sys.addaudithook`) sees every process start of the process, whoever starts it: `subprocess` (on Windows the event carries the command line `list2cmdline` built, which is split back on its quotes), `os.system`, `os.exec*`, `os.spawn*`, `os.posix_spawn`, `os.startfile`. A git call that can change a ref, HEAD or a remote (init, fetch, checkout, commit, branch, remote, push, merge, and every subcommand not on the read-only list), a test's own `git` helper, the model's session and any non-git process all move the generation on, and the next lookup asks git again. `config`, `remote`, `branch` and `symbolic-ref` count as read-only only in their reading forms; anything the hook cannot parse counts as a change. An answer asked while the generation moved is not stored.
- **Remembered:** `gitops.default_branch` (the guess; `SDLC_DEFAULT_BRANCH` is read every time), the new `gitops.origin_head` and `gitops.ref_exists`, which `default_branch`, `gate/diff.py`'s `default_base` and `run_phase._ref_exists` now share. `gitops.is_repo` keeps a yes for good with the git directory git named (`rev-parse --is-inside-work-tree --absolute-git-dir`), re-checked by a stat that the directory still exists; a no is always asked again, so a later `git init` is seen. `gate/diff.py`'s `is_repo` is `gitops.is_repo`.
- **Tests:** `tests/test_gitops_lookups.py`, 35 tests: a repeated lookup with only read-only queries in between asks git once; `is_repo` follows `git init` and a removed `.git`; `default_branch` follows a checkout, a branch made by gitops' own call and by a test's own git, a remote added, a push and `remote set-head`; `ref_exists` follows a push, a fetch, a merge, `update-ref -d` and gitops' own commit; a non-git process forgets every answer; the explicit default branch is never remembered; 29 cases of the read-only classification, the Windows command-line forms among them. With the audit hook's effect removed, the three staleness tests fail (checked by hand in a cloud session, then restored).
- **Measured in a cloud session (Linux, 4 cores), with the same method as #248** (a `sitecustomize` that logs every `subprocess.Popen`, `GIT_CONFIG_GLOBAL` an empty file, `GH_TOKEN` and `GITHUB_TOKEN` unset, `python -m pytest -n auto --dist worksteal`), on #248's head `af0524b` against this change on top of it: the suite started 36,930 processes, 34,286 of them git, against 31,520 and 28,874 (`rev-parse --is-inside-work-tree` 3,616 to 1,139, `rev-parse --verify` 4,431 to 2,445, `symbolic-ref` 2,303 to 1,478). The end-to-end test above: `--is-inside-work-tree` 53 to 16, `--verify --quiet refs/remotes/origin/main` 51 to 22, every git process 374 to 296.
- **Its time on Linux is within the noise:** alternating runs, total test time 496 s and 530 s against 517 s and 510 s, wall time 133 s and 147 s against 143 s and 140 s. About 5,400 fewer git processes at a few milliseconds each on Linux is under the runs' own spread; the target is Windows, where each process start costs several times more. Each timing run first removed the earlier runs' pytest base directories: the fixture project's own `python -m pytest`, run by the gate's commands step, uses `tmp_path`, and pytest then deleted the oldest base directories (about 900 MB each in this sandbox), which put 15 to 20 s into a random end-to-end test.

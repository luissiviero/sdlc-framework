## The optional item: why a park of its own
Recommended and built: **a park of its own, limited to the models `sdlc.yaml` names.**
- **For.** The `reviewer_model` park the fallback causes says "the adversarial reviewer ran on claude-fable-5-1, not on claude-opus-5-5" and points to `panel/cli.py models` and the configuration; on 0017's design run the cause was the CLI, read only in `claude-b.stderr.txt`, and the fix was raising `plugin.claude_code` (NOTES §54). The `cli_model` park names that fix. It also covers the advocate (the `panel_models` park says only that no model of the run matched). The next model id the template names meets the same gap on any pinned CLI, so the check outlives R63's default.
- **Against, and why it does not apply.** A park on any `unrecognized_model` line would park on a model nobody configured (a built-in sub-agent's, a future CLI's internal id); the filter keeps only the three configured models, so a line for any other model is ignored (the second case of the runner test). A stale stderr cannot trigger it: the check reads the stderr of the run that just ended (`invoke`'s output), never a stored file.
- **Size.** 31 lines added in `plugin/panel/models.py` (the docstring included), 24 in `plugin/ci/run_phase.py`, three tests.

## The two workflows that install 2.1.278 (the task's item 6)

- `.github/workflows/substrate-smoke.yml` runs one headless turn (`.github/scripts/substrate_smoke.py`, `--model opus --max-turns 2`): no sub-agent.
- `.github/workflows/framework-evals.yml` runs `plugin/evals/run.py --fixture`, which passes `--model` only when `SDLC_MODEL` is set (the workflow sets none) and sets no `ANTHROPIC_DEFAULT_<FAMILY>_MODEL` pin; the plugin's agents name `opus` (the adversarial reviewer) or `inherit` (`plugin/agents/*.md`). The full id reached the reviewer on 0017 through the runner's alias pin (`alias_pins`), which the eval runner does not set, and no eval case asks for a sub-agent by a full id (`evals/cases/*/prompt.md`).

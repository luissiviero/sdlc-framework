- **Three tests called the real `gh` (point 5, re-measured and corrected).** A logging `gh` shim first on PATH, recording `$PYTEST_CURRENT_TEST`, found 51 calls, all from `test_a_run_that_leaves_no_gate_file_is_an_infrastructure_failure`, `test_a_failing_claude_run_exits_1_with_its_text_on_stderr` and `test_the_review_pass_commits_its_own_result_record_and_spend_entry` (`tests/test_ci.py`): three `gh pr list --repo owner/name` (one per test, from `find_open_pr` before the session starts) and 48 `gh label create` (sixteen per test, from `ensure_labels`), every one exiting 1 after a failing request, 18.2 s inside `gh` in all, and the three were the suite's three slowest tests (15.15 s, 12.98 s, 12.26 s). **The correction:** `ensure_labels` runs only with a token in the environment, and the 48 label calls (and the token route's own HTTP requests before each of them) happen because this cloud container carries `GH_TOKEN`, which `conftest.py` does not strip (it strips `GITHUB_*`). On the GitHub runner no token is set, so the three tests make only the three `gh pr list` calls, each answered in about 0.05 s with the sign-in hint and exit 4, no network. The fake `gh` therefore buys the Windows job nothing measurable; it buys a suite that reaches GitHub from no machine.

With it, the shim recorded zero real `gh` calls over the serial and the parallel run. `framework-checks.yml` is unchanged: it installs the dev extra and runs `python tasks.py check`.

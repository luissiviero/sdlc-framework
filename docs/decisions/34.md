## 34. The owner's `@claude` comment starts a fix round, and only the owner's account starts a round or approves (c) and (d) (amends 22 and 27)

*Reference: steps 8, 11, 26, 27, 28, 30 · NEW (2026-10-17), from study entry T17 (crosswalk row deploy-comments), ROADMAP R17 (`docs/proposals/claude-comment-fix-round.md`); the narrowing of the (c) and (d) labels from the owner's decision table of 2026-10-16 (`docs/handoffs/sessions/2026-10-15-ccr-01de3f80-ilnomi.md`, line 30)*

- Today (decisions 22 and 27): a fix round starts on a "Request changes" review by any member or collaborator who is not a `[bot]` (`template/.github/workflows/sdlc-fix.yml`, its job `if:`), on a `workflow_dispatch` of `sdlc-fix.yml`, or on an un-park label. The labels `sdlc:c-approved` and `sdlc:d-approved` count from any person who is not the workflow token. GitHub refuses "Request changes" on the reviewer's own pull request (`docs/notes/29.md`), so on an intent PR the owner opened by hand the owner writes a comment review and then dispatches the round by hand from the Actions tab: two acts in two places.
- **Accepted:**
  1. **One trigger added.** A comment in a pull request's conversation (`issue_comment` `created`) whose body starts with `@claude`, by the owner's account, starts the same fix round as the owner's "Request changes" review, on every phase's PR. Only `created` counts, so one comment is one round; a line comment is read by the round as today and is never a trigger.
  2. **A dispatcher with no model.** A small workflow runs on the comment, checks out the default branch and never the PR's head, and dispatches `sdlc-fix.yml` with the change id, the head branch and the comment's link, as the owner does by hand today. It refuses, each with its reason and as a green skip, a PR that is not open, a head in another repository, and a PR with no change folder or with several.
  3. **The owner's account only.** Only the owner's account starts a round, on the comment path and on the "Request changes" path, and only the owner's account approves gates (c) and (d) with their labels. The owner is the repository owner by default; an organization repository names the owner in `sdlc.yaml: owner`, read from the default branch's copy (a guardrail edit). One function, `is_owner_actor`, beside `is_automation_actor`, decides it and fails closed; a workflow's `if:` keeps only a coarse check. R22 (T18) and R41 (T24) call the same function when they are built. Whose words reach a round stays the member rule of `plugin/ci/fix_requests.py`.
  4. **A trigger, never a verb.** The comment accepts and waives nothing; no workflow parses anything after the prefix; the words after `@claude` are a constraint like any review comment, read as data.
  5. **One counter.** The round counts one iteration and shares decision 29's counter; decision 29's one reset at the cap is for the automatic rounds only.
  6. **No request applied twice.** A PR comment cannot be resolved and a comment review cannot be dismissed, so the round marks each request it applied in the committed `fix-requests.json`, and the next round lists an earlier round's applied request without its text.
- Rejected: a round per comment, as the article's (more runs and many small pushes to follow); `issue_comment` added to `sdlc-fix.yml` itself (the payload carries no head, so the group, the checkout and the head would need a second shape); a line comment as a trigger; keeping the member rule for starting a round; a reply or a reaction from the round to say it started (a notification, decision 20).

**Why:** The owner's note on the crosswalk row deploy-comments: "my comment starting with '@claude' on a change's PR starts the same fix round … the workflow checks the comment came from my account (not just any person) and reads its text as data. It replaces the manual workflow_dispatch on PRs I opened by hand, where GitHub refuses my own 'Request changes'" (`docs/reviews/2026-09-28-playbook-vs-framework/target-design.md`, T17). The article's loop is a comment: "When a reviewer or the author tags @claude on a review comment, Claude addresses the comment and pushes the fix" (p.33 step 4). Decision 22 already reads "the owner's" review; the member rule was the fix workflow's narrowing from anyone, and on a public repository it lets a collaborator start a privileged run on a head of their choosing. Decision 27 left "whether the actor must be the owner's own account" to T17, T18 and T24; the owner chose the owner's account on 2026-10-16, built with R17's check.

**What it gives up:** GitHub starts a run of the dispatcher for every comment on every issue and PR, skipped at once by its `if:`; an organization repository needs one `sdlc.yaml` key; a collaborator can no longer start a round or approve gates (c) and (d).

**What it amends:** decision 22 (one trigger added, and both triggers become the owner's alone; the round, the command and the record are unchanged) and decision 27 (the label's actor must be the owner's account). Kept: 24 and 28 (the comment is a trigger, not a verb), 29 (one counter, the same dispatch), 11 and 20 (a park at the cap, no reply, no notification), 5 (the automation identity is still refused).

**To verify before the design:** an `issue_comment` run on the sample, recorded in `docs/notes/`: which workflow file it uses (the default branch's, by GitHub's documentation, not verified here), and its token on a PR from a fork. The dispatcher refuses fork heads whatever the answer.

**Accepted:** the owner, 2026-10-14 (R17 accepted as recommended, PR #208), and 2026-10-16 (the decision table, the narrowing of the (c) and (d) labels "built with R17's owner check"). Written as a decision file on 2026-10-17, before R17's build, in a documentation PR of its own.

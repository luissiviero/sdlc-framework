## 44. Facts read on 2026-10-14 for plugin 1.0.1: where a sandboxed CI session may write, what gh run view --log-failed writes, and the cache folder the runner now gives the session

The full reading, with every not-verified point, is `docs/handoffs/2026-10-14-gh-cache-1.0.1-part-1.md`. The gap is NOTES §43's: change 0014's diagnosis on the sample could not create `/home/runner/.cache/gh`.

- **Where a sandboxed command may write** (verified, https://code.claude.com/docs/en/sandboxing, read 2026-10-14, the "What the sandbox restricts" table and "Configure sandboxing"): the working directory, a per-user temp directory, and directories added with `--add-dir` or `permissions.additionalDirectories`. `$HOME` and `/tmp` are not among them. Claude Code sets `$TMPDIR` to the per-user temp directory for sandboxed commands ("Temporary directories"). Its exact path on the runner is not verified.
- **The parent's environment reaches sandboxed commands** (verified, the same table: "Inherited from Claude Code, including any secrets in its environment"; sandbox-runtime 0.0.79 `linux-sandbox-utils.js:2676-2680`). Only `sandbox.credentials` or `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` strip a variable, and the CI settings set neither.
- **Why the model could not set the variable itself** (the rule is verified, https://code.claude.com/docs/en/permissions, "Bash rules"): an allow rule does not match past a leading assignment of a variable outside a known-safe set. So `XDG_CACHE_HOME=… gh …` did not match `Bash(gh *)`, and `--permission-prompts none` denied it. The three denials themselves were read by the item-11 session (NOTES §43).
- **What `gh` writes for `run view --log-failed`** (verified, cli v2.89.0 `pkg/cmd/run/view/view.go`; go-gh v2.13.0 `pkg/config/config.go`):
  - On a cache miss, `os.MkdirAll(<cache>, 0755)`, then `<cache>/run-log-<run id>-<started>.zip`. The zip is always read back from disk, and a failed `MkdirAll` aborts the command.
  - `<cache>` is `$XDG_CACHE_HOME/gh`, else `$HOME/.cache/gh` on Linux. `GH_CACHE_DIR` does not exist. `XDG_CACHE_HOME` is not listed in `gh help environment` (2.89.0).
  - Nothing else is written for this call (verified, `strace` under an empty or read-only `HOME`, both exit 0): the config dir is only read, the update check is skipped when `CI` is set or there is no TTY, and the extensions dir is only `stat`ed.
  - Other `gh` versions are not verified.
- **1.0.1's fix** (choice 195, option A; `plugin/ci/run_phase.py`): `session_env` sets `XDG_CACHE_HOME` to `<root>/.sdlc-cache`, inside the checkout, which is already a write root. It replaces any value the workflow set. `RUNNER_EXCLUDES` gains `/.sdlc-cache`, so the gate never sees the folder and commit-phase never stages it. No sandbox or permission entry is added, and `settings.ci.json` is unchanged.
  - Tests: `test_the_session_s_gh_cache_is_a_folder_the_sandbox_lets_it_write`, the updated `test_the_session_s_environment_leaves_the_gate_s_commands_to_the_runner`, and a cached zip in `test_the_run_excludes_the_runner_s_own_untracked_entries_once`, all in `tests/test_ci.py`. All three failed on 1.0.0's code.

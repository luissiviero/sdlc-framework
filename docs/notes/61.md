## 61. Facts read on 2026-10-23 for ROADMAP R27: how a skill load shows in a headless run's output

### evals
- **A skill the model loads is a `Skill` tool call whose input names it in `skill`** (verified, `cc-permissions`): "A `Skill(skill:<name>)` deny rule instead matches the skill under any of its names, such as its alias or display name", and a parameter rule names "a direct field of the tool's input". The documentation's own trigger test is "an eval case with a `tool_used: Skill` grader" (`cc-skills`), the option `docs/notes/13.md` keeps.
- **A plugin's skill is named `plugin:skill`** (verified, `cc-sdk-skills`: "Use `plugin:skill` for plugin-provided skills"). The framework's skills load as `sdlc:<name>`, and a project's own skill by its bare name, so the runner's `skill` check matches the name exactly: the framework's cases name `sdlc:<name>`, and a project's case for its override names the bare name, which the plugin's copy does not satisfy.
- **The older input field** (not verified): builds before the `skill` field are taken to have sent the name as `command`, with a leading `/`. The runner reads `command` when `skill` is absent. Nothing in the pages read confirms it, and nothing depends on it once the live run below shows `skill`.

### cli
- **The tool calls are in the assistant messages** (verified, `cc-streaming`): an assistant message carries its content blocks, and a tool call is a block with `type: tool_use`, its `name` and its `input` (`message.message.content` in the TypeScript SDK's own example). A call's result comes back in a `user` message as a `tool_result` block naming the call's id; the runner does not count a `Skill` call whose result has `is_error` set (not verified: the field is the Messages API's, and no failed `Skill` call has been observed in a run).
- **Only a verbose run prints them** (verified, `cc-best-practices`): "The `json` format returns a single JSON object with a `result` field", and the result message carries no tool calls. `--output-format stream-json --verbose` prints "one JSON object per line, starting with an init event". The runner already reads `--output-format json --verbose` as a list of messages (`runner`), so R27's runner adds `--verbose` to a case with a `skill` check and reads both shapes: one list, or one message per line.

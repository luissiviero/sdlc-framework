## 57. Ruleset 1's two bypass modes for the owner, tested live (2026-10-22)

### rulesets
- **The setup** (verified, the owner's screenshot of ruleset 24077592): "Restrict updates", "Restrict deletions", "Require a pull request before merging" and "Block force pushes", target the default branch, one bypass actor, the Repository admin role. The owner set its mode for each run.
- **A cloud session acts as the owner's login on both of its routes** (verified, `probes`, `rule-suites`): the GitHub MCP tools (as NOTES §14 recorded) and the session's git proxy. Every rule-suites entry of the session's writes names `luissiviero` as actor. The git commit's author is the only trace of the session (`Claude` on `906317a`), and the session sets it itself. The pull requests the session opened read the owner as their author.
- **"For pull requests only" refuses a direct write by anything acting as the owner** (verified, `probes`): the session's `create_or_update_file` on `main` answered `409 Repository rule violations found` ("Cannot update this protected ref. Changes must be made through a pull request."), and its `git push origin HEAD:main` ended in `push declined due to repository rule violations`. The proxy let the push through to GitHub, so the ruleset was the only refusal.
- **Exempt accepts both** (verified, `probes`): the same two writes landed on `main` as `7c33f02` and `906317a`, and #316 removed them.
- **Neither mode stops an API merge by a session acting as the owner** (verified, `probes`): in "For pull requests only", #314 read `mergeable_state: blocked` through the session's tools, and `merge_pull_request` merged it (`54a05f6`). In Exempt, the same call merged #316 (`1cdb45f`). The bypass in "For pull requests only" covers any merge of a pull request, not only the web UI's checkbox. This answers, for the owner's login, the question that choice 249's point 4 leaves open for the merge App: whether an API merge goes through in this mode. The App is a different actor, so its first merge still verifies it.
- **The phone merges in both modes** (verified, `owner`, `probes`). This closes NOTES §17's open point. In "For pull requests only" the GitHub mobile app shows "Unable to merge — Cannot merge at this time" and still offers Merge. A tap opens the commit-message sheet, and its MERGE button merged #315 (`merged_by: luissiviero`). In Exempt, #318 read `mergeable_state: clean`, the app showed "Ready to merge", and the same sheet merged it.
- **The web editor commits to `main` directly only in Exempt** (verified, `rule-suites`): the owner's two "Update CLAUDE.md" commits of that afternoon (`2cf98e3`, `396e4b4`) were made in Exempt mode and read `pass`. In "For pull requests only", the same edit needs a pull request (as S1 shows for the API).
- **Option C: Exempt in ruleset 1, plus the no-direct-writes rules in a ruleset where the owner's bypass is "For pull requests only"** (verified, `probes`, `owner`, the four rulesets' exports and `GET /repos/<repo>/rules/branches/main`):
  - The rules are "Require a pull request before merging" (no approvals), "Block force pushes" and "Restrict deletions". On this repository they are a new ruleset, 25674595 "main — no direct writes (choice 251)". On the sample they were added to ruleset 2 (25656269), renamed "review and no direct writes on main (decision 36, choice 251)".
  - The session's direct commit was refused on both repositories (`409`):
    - here with "Changes must be made through a pull request." only, since ruleset 1 no longer applies to the owner's login;
    - on the sample also with "Required status check "sdlc/review" is expected."
  - On the sample, an ordinary pull request (#101) read `blocked` until its "not a build PR" check was posted, then `clean`, and the owner's app showed "Ready to merge". Sample #55, with no `sdlc/review`, showed "Unable to merge". So in C the label shows ruleset 2's verdict alone. In "For pull requests only" on ruleset 1 it would read "Unable to merge" on every pull request.
  - The `git push` (S2) was not tried in C: the session's own safety check refused it.

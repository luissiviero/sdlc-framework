## 58. The merge-tool deny rule binds a cloud session's GitHub tools (2026-10-23)

### permissions
- **The rule** (verified, `settings`): `.claude/settings.json` on `main` denies `mcp__github__merge_pull_request` and `mcp__github__enable_pr_auto_merge` since #328, the owner's row 5 of choice 253's record. The user-level `~/.claude/settings.json` of the session's container denies neither, so the project file is the rule's only source.
- **It binds by removing the tools** (verified, `session`, Claude Code 2.1.309). Before the rule reached the session's checkout, both tools were in its deferred tool list and loadable. Once the checkout held `main` at `26f03c1`, the harness reported both as no longer available. `ToolSearch` for the two tools and `get_me` returned `get_me` alone, so the GitHub server was connected and only the two denied tools were gone. The session never called a merge tool for this check.
- **It binds a session whose checkout holds the rule.** A session on a branch cut before #328 reads that branch's `.claude/settings.json`. Every branch cut from `main` after #328 carries the rule.

### github-api

In a cloud session, `gh` reaches GitHub through the session's proxy: `gh run view` worked, although `gh auth status` reports `GH_TOKEN` as invalid. Whether the proxy's credential lets `gh pr merge` or `gh api … /merge` write is not known. The only test is a merge attempt, which the session did not make, and its read of `gh api user` was denied by the permission system.

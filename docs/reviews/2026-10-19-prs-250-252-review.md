A fresh-context review of the framework's last three merged pull requests. It reports and fixes nothing. Each PR was read in its description and in its merged diff (the merge commit against its first parent: #250 `22d99fc`, #251 `b1ae336`, #252 `7960377`), against `docs/OPERATING_MODEL.md` and `docs/decisions/index.md`.

**Assumptions** (where the task left room, the reading a careful reviewer would take):
- "The last three merged PRs" are the three the task names. `main` was at `7960377` when this review was written.
- Measured figures were not re-run: the process counts and the Linux and Windows timings in #251, and the owner's screenshots in #250. Every other claim was checked against a file, a git object or the GitHub API, as cited in each row.
- Severity: **Important** means act on it before the work it affects; **Minor** means a real gap with no live failure path today; **Nit** means wording, a test name, or a path that needs contrived input.
- Experiments ran on a scratch copy of the tree, never on this branch. One example: `plugin/state/gitops.py` with the hook's `_generation += 1` replaced by `pass`.

## Verdicts

- **#250, NOTES §50 (change 0016 on the fast lane at 1.0.12; R47's push settings): sound with notes.** Documentation only. The claims I could check hold:
  - `v1.0.11` is an ancestor of `v1.0.12` (`90cfd1d`).
  - #77 was opened by the owner's account and closed by the App: `closed_by: sdlc-automation-luissiviero[bot]` in the issues API.
  - §49's two bullets are annotated inline, which the notes convention allows. The index was regenerated.

  Two facts the note recorded, or could have, are not followed through: the operating model still says the workflow token closes a superseded intent PR, and #77's own body told the owner "merge = approve (gate (a))" after the fast lane had already accepted the intent.
- **#251, gitops: remembered git lookups, plugin 1.0.13: sound with notes.** The diff implements what the description claims:
  - The audit hook bumps a generation on every process start except a read-only git query.
  - `default_branch`, `origin_head`, `ref_exists` and `gate/diff.py`'s `default_base` share the remembered answers, and `run_phase._ref_exists` uses them.
  - `is_repo` keeps a yes behind a stat of the git directory.
  - There are 36 tests. With the hook's effect removed, the three staleness tests fail, as the description says. The audit-event test fails too, so 4 fail in all (reproduced).
  - Windows is handled: there the `subprocess.Popen` audit event carries the `list2cmdline` string, which `_reads_only` splits back. The Windows shard runs `test_a_repeated_lookup_with_nothing_in_between_asks_git_once` with real events, so a misreading on Windows would fail that test.
  - Nothing moved into `template/`. No decision is reopened: choice 235 asked for this change, with a version bump.

  The notes: `gate/diff.py` lost its 60-second git timeout. The "every process start" invariant is wider than what the hook sees. One test asserts less than its name says. Two edge paths give a wrong answer only on contrived input.
- **#252, ROADMAP Order before the real-project trial (choice 238): a finding to act on.** The rank arithmetic is right:
  - Ranks 12 to 28 are each used once.
  - Old ranks 12–18 and 21–27 each move down by one.
  - Every changed cell keeps its previous value.

  The problem: R44 now sits at rank 12, ahead of R27 at rank 19. R44's own scope includes the `denyWrite` entry for R27's `policies/` sources, and the decision table of 2026-10-15 records that dependency. The move inverts it and does not say so. Separately, the session file quietly moves the sandbox proof from "before rank 7" to rank 12.

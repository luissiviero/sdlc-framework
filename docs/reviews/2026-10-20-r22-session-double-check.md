### Guarantees checked that hold
- **The doorbell holds no key and dispatches on the default branch only.** It has no environment and no secret (`sdlc-merge.yml:59-98`, asserted in `tests/test_templates.py`). The owner is judged by `is_owner_actor` on the default branch's `sdlc.yaml`, the head must be `sdlc/<id>/c`, and the PR must come from the same repository (`merge_step.py:183-233`).
- **The key is read in one step of the merge job only** (`sdlc-merge.yml:136-164`). That job runs on `workflow_dispatch` at the default ref only (`:139-141`), in `sdlc-merge` (`:144`). It runs the default branch's content and the pinned public framework, never the PR's head (`:166-189`). The inputs reach the script as environment variables, and `--pr` is parsed as an integer (`merge_step.py:443`).
- **The workflow token never merges.** Reads use `GITHUB_TOKEN`; the merge uses `SDLC_MERGE_TOKEN` alone (`merge_step.py:413-416`).
- **Only the owner's latest decisive review counts.** COMMENTED is ignored; CHANGES_REQUESTED and DISMISSED revoke; a `[bot]` and the automation never count (`merge_step.py:164-179`, `state/unpark.py:101-115`). An organization repository without `owner:` fails closed.
- **A push after the approval, or a stale approval, is refused.** After the approved commit and after the reviewed commit, only evidence, `status.yaml` or `.review-seen.json` may follow (`merge_step.py:141-161`, `:355-360`, `:375-380`). The compare must be ahead or identical, so an "Update branch" or a force-push is refused (`:152-153`). Renames list both paths, and more than 300 files fails closed (`pr/github.py compare_commits`).
- **The merge is pinned to the judged head.** `sha` is passed to `PUT /pulls/{n}/merge`, so a push between the check and the merge gets a 409 (`merge_step.py:416`).
- **Only an open, ready build PR at (e) merges** (`merge_step.py:287-354`). It must be open and not a draft, with its head in the repository and the default branch as its base. It must carry `sdlc:e-ready` and not `sdlc:needs-human`. Its `status.yaml` must read e/passed, not parked, with `build_pr` naming it. `gate-e.json` must say `wait` with no deferred commands check, and no Important finding may stand. Every `sdlc/review` run on the head must be green (`:361-368`).
- **Forks are skipped** (`merge_step.py:213-216`, `:246-252`, `:294`), and each PR's merges are serialized (`sdlc-merge-<pr>`, `sdlc-merge.yml:145-148`).
- **`check-run --final-head` and `offer_merge`.** The final-head check requires the reviewed commit to be an ancestor and lists paths with `git diff --no-renames`, matching the merge step (`review/cli.py:274-299`, `:320-332`). `offer_merge` (`run_phase.py:5109-5140`) runs after the runner's last commit and push. It dispatches only on a green check and a gate (e) that says `wait` (`:3434-3443`), with inputs that match the workflow's.
- **`app_missing`** (`ci/app_token.py:287-298`) is right for the callers it has: `run_phase.py:5511`, `detect/cli.py:649` (`run --file`) and `scan/cli.py` (`route`). F4 is the caller it lacks.
- **A `[bot]` merge accepts no risk.** The release requires the owner's latest decisive review (`release/cli.py:436-452`, `:470-494`), and the baseline check rejects a `[bot]` as `by` (`run_phase.py:4095-4107`). F2 is what that check still lets through.
- **The repository's copies of the workflows equal the templates**, and `sdlc-merge.yml` is deliberately absent from this repository (`tests/test_templates.py:305-310`).
- **The digest line** reads the owner the same way (`is_owner_actor`, the latest decisive review), and `sdlc-digest.yml` gained `checks: read`.

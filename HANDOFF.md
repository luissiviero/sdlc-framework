## Session 10 — the first real detection and the bump (on the first judging day, 2026-10-11 if the schedule held; start after 06:30 UTC so the 05:41 run and the 06:17 digest are done)

Why the day before: the statistics need the bad day to be a complete UTC day (choice 82) and the tail's latest point. With a flat all-zero baseline any failure is an infinite-sigma point, a **3σ** breach that files at tier 3, propose (`stats.py` docstring, the article's own example p.45: one failure after a clean run). The baseline is flat only if no person-run `CI` failure landed between 2026-09-25 and 2026-10-02 (session 9's pushes fall in that span): session 9 reads the days' rates and, if a baseline day has a failure, says in its brief what rate the bad day needs (the latest point trips `we1` at three sample sigmas above the mean; one failing `pull_request` run against the scheduled pass gives 0.5; a second commit pushed to the PR gives a second failing run and 0.67, which clears one baseline failure among many passes). ## Rules for these sessions
- Never reopen a decision; a decision a live run shows impossible as built is documented in PROGRESS.
- Cite the PDF page whenever the article is used.
- No notifications, no bypass-permissions mode, no third-party runtime dependency, Python for every script, workflows whose `run:` lines call `python` (and the pinned `claude` install) only — the one exception is the pin step's `git show … | python -` line under `shell: bash` (choice 95) — never with a `${{ }}` in the line (an `env:` value may carry one).
- Guardrail files here and in the sample (`CLAUDE.md`, `.claude/**`, `REVIEW.md`, `sdlc.yaml`, `bands.yaml`): the owner's edit, given as "link; row; what is there; what it needs to be". The sample's `ci.yml` is project content, not a guardrail, but the edit of precondition 0 is given the same way because the sample is out of this session's reach.
- One open incident per metric (choice 69): a real finding blocks the metric until its PR is triaged; triage it (merge, `schedule` or close) before expecting the next filing, and remember that a close with a comment dismisses its signature for one window. A rehearsal is closed without a comment (choice 86) and never left open overnight on the road to the first real detection.
- The shakedown method of session 6 (choice 88) when a fix must be live-tested before the tag: a sample branch whose `sdlc-detect.yml` checks out the framework at the branch under test, dispatched with that ref.
- A version is bumped only for a change in `plugin/` or `template/`; the 1.0.0 bump is the one exception and belongs to session 10's PR alone (a bump PR of its own only if session 10's fix PR is not the same PR).
- Every PR: `python -m compileall -q plugin tests tasks.py .github/scripts`, the full `python -m pytest`, `python -m ruff check .`, `python -m ruff format --check .` — green before the push, chained on the exit codes; a fresh-context Opus review of the diff before the final commit; a draft PR against `main`.
- The secrets-check hook refuses any file whose text contains a credential-shaped string: describe a key in words.
- An environment fact (what the container can reach or run) is recorded in NOTES with its read date and re-tested only when the date is older than the environment's last change (choice 93).
- What a session cannot prove it writes as "not verified" with the reason; a fact is "verified" only with the run URL, the file or the command output that showed it.

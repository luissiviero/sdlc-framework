## Rules for these sessions
- Never reopen a decision; a decision a live run shows impossible as built is documented in PROGRESS. The review's "ruled not a problem" list is settled the same way.
- Cite the PDF page whenever the article is used.
- No notifications, no bypass-permissions mode, no third-party runtime dependency, Python for every script, workflows whose `run:` lines call `python` (and the pinned `claude` install) only — the one exception is the pin step's `git show … | python -` line under `shell: bash` (choice 95) — never with a `${{ }}` in the line (an `env:` value may carry one).
- Guardrail files here and in the sample (`CLAUDE.md`, `.claude/**`, `REVIEW.md`, `sdlc.yaml`, `bands.yaml`): the owner's edit, given as "link; row; what is there; what it needs to be".
- The freeze of precondition 6, until item 11.
- A kept record (a PROGRESS session, a NOTES fact) is annotated beside the sentence, never rewritten (choice 126); a NOTES fact keeps its read date and is re-tested only when the date is older than the environment's last change (choice 93). `docs/PROGRESS.md` holds the current record only: the session that writes a new record moves the previous one to `docs/progress/` unchanged and adds its line to the index (change 0001's rule).
- One open incident per metric (choice 69); a rehearsal is closed without a comment (choice 86).
- The shakedown method of session 6 (choice 88) when a fix must be live-tested before the tag — on this repository, never on the sample before item 11. A gap that does not change a gate's verdict waits for the tag (choice 163).
- A version is bumped only for a change in `plugin/` or `template/`; change 0003 is 0.3.6 (bound by its intent and spec) and `v0.3.6` carries PR #130's push-check fix and PR #133's reviewer-prompt fix, both merged unbumped (choice 168); the carried gaps are 0.3.7; the 1.0.0 bump belongs to item 11's PR alone.
- A by-hand `sdlc-fix.yml` dispatch without `head_ref` is run **from the pull request's head branch** ("Use workflow from"): the runner reads the head from that branch's open pull request (PR #130); from the default branch the checkout has no change folder and the run skips ("no change folder for id").
- Every PR: `python -m compileall -q plugin tests tasks.py .github/scripts`, the full `python -m pytest`, `python -m ruff check .`, `python -m ruff format --check .` — green before the push, chained on the exit codes with `set -o pipefail` (a `tail` pipe hid two failures in session 15); `claude plugin validate .`; a fresh-context Opus review of any diff that touches `plugin/` or `template/` and of any design the framework writes (`model: "opus"`), each finding reproduced before it is acted on; a draft PR against `main`; all three jobs of `framework-checks.yml` green on the PR's final head before the owner is asked to merge (a docs commit after that read starts them again: read again).
- In a plan or an intent, no continuation line of a list item starts with a digit followed by `.` or `)`, `-` or `*`: the gate's list-item regex reads it as an item (`docs/progress/session-20.md`, Known gaps), until 0.3.7 fixes the regex.
- A design that passes gate (b) but cannot be built as written gets a second review, not a merge (choice 164): the build may update `plan.md`, never `spec.md`. A build PR parked at (e) gets a reset and a round, not a merge over the parked gate (choice 169).
- A fresh-context reviewer grades a finding on its own: a repeated nit is a nit; the second-occurrence rule is `validate`'s, across changes (PR #133; the root `REVIEW.md` row). A reviewer's severity is a claim to check against `plugin/review/findings.py` before the gate's park is taken as the framework's verdict.
- The secrets-check hook refuses any file whose text contains a credential-shaped string: describe a key in words.
- What a session cannot prove it writes as "not verified" with the reason; a fact is "verified" only with the run URL, the file or the command output that showed it.
